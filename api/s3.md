# File Sign API

All endpoints require:

```text
Authorization: Bearer <access_token>
```

Successful responses use the common response envelope:

```json
{
  "code": 0,
  "data": {},
  "message": "Success"
}
```

Error responses use:

```json
{
  "code": -2,
  "message": "invalid request parameters"
}
```

## Storage Layout

Configured storage categories select the real bucket only on the server:

```text
avatar:
  {key_prefix}/{user_scope}

image:
  {key_prefix}/{user_scope}/images/{sha256}.{ext}

document:
  {key_prefix}/{user_scope}/docs/{sha256}.{ext}

media:
  {key_prefix}/{user_scope}/media/{sha256}.{ext}
```

Storage providers:

Credentials are configured in `config/keys.toml` or on each resource bucket.
When `keys.toml` exists, its `access_key` and `secret_key` override every bucket
so all resources use the same credentials. Without that file, every bucket must
contain its own `access_key` and `secret_key`.

For shared credentials, copy `config/keys-example.toml` to `config/keys.toml` and
fill in the key pair. Keep `keys.toml` out of version control.

```toml
[s3]
# Shared defaults are optional. Values on a bucket override these defaults.

[[s3.buckets]]
id = "avatar"
bucket = "avatar-bucket"
read_policy = "private" # public or private
key_prefix = "avatars"
provider = "s3"
endpoint = "https://avatar-storage.example.com"
internal_endpoint = "http://avatar-storage.internal:9000"
addressing_style = "path" # use virtual_host for providers such as Tencent COS
region = "us-east-1"
access_key = "avatar-access-key"
secret_key = "avatar-secret-key"

[[s3.buckets]]
id = "image"
bucket = "image-bucket"
read_policy = "private"
key_prefix = "users"
provider = "s3"
endpoint = "https://image-storage.example.com"
region = "us-east-1"
access_key = "image-access-key"
secret_key = "image-secret-key"

[[s3.buckets]]
id = "document"
bucket = "document-bucket"
read_policy = "private"
key_prefix = "users"
provider = "cloudflare_r2"
endpoint = "https://<account_id>.r2.cloudflarestorage.com"
region = "auto"
access_key = "document-access-key"
secret_key = "document-secret-key"

[[s3.buckets]]
id = "media"
bucket = "media-bucket"
read_policy = "private"
key_prefix = "users"
provider = "s3"
endpoint = "https://media-storage.example.com"
region = "us-east-1"
access_key = "media-access-key"
secret_key = "media-secret-key"

```

Each resource bucket can use a different S3-compatible provider and credentials.
`provider` is a free-form provider identifier, for example `aws`, `tencent_cos`,
`minio`, `rustfs`, or `cloudflare_r2`. The endpoint, credentials, region, and
addressing style define the connection. For Cloudflare R2, set the account
endpoint and `region = "auto"` (or omit the region to use `auto`).

All configured resources use the same `/file/sign/...` API. `endpoint` is
browser-facing: returned signed URLs and fallback object URLs use that resource's
endpoint. When configured, `internal_endpoint` is used only by file-service's
server-side `HEAD` and `PUT` requests; it defaults to that resource's endpoint.
`read_policy` controls only read behavior. All uploads, overwrites, and deletes
remain authorized by file-service using the caller JWT and generated object key;
clients never submit a real bucket name. `user_scope` is derived from the JWT
subject. When the subject is a UUID, the UUID `u128` value is encoded as Base62.

Clients must not submit S3 paths. The server owns bucket and key generation.

## GET /file/sign/upload/avatar

Returns a PUT signature for the current user's avatar object.

The avatar object key is stable, so uploading a new avatar overwrites the old one.

Query parameters: none.

Response `data`:

```json
{
  "bucket_id": "avatar",
  "method": "PUT",
  "upload_url": "http://127.0.0.1:9000/public-bucket/avatars/{user_scope}",
  "key": "avatars/{user_scope}",
  "already_uploaded": false,
  "headers": {
    "authorization": "AWS4-HMAC-SHA256 ...",
    "x-amz-date": "20260520T000000Z",
    "x-amz-content-sha256": "UNSIGNED-PAYLOAD",
    "Content-Type": null,
    "Content-Disposition": "inline"
  }
}
```

## GET /file/sign/upload/image

Returns a PUT signature for an image object.

Query parameters:

| Name | Required | Description |
| --- | --- | --- |
| `filename` | yes | File SHA-256 digest as 64 lowercase or uppercase hex chars. A trailing `.sha256` suffix is accepted and removed. |
| `ext` | yes | One of `jpg`, `jpeg`, `png`, `webp`, `gif`. A leading `.` is accepted and removed. |

The server checks whether the object already exists in S3. If it exists, `already_uploaded` is `true`; the client can skip uploading.

Response `data`:

```json
{
  "bucket_id": "image",
  "method": "PUT",
  "upload_url": "http://127.0.0.1:9000/private-bucket/users/{user_scope}/images/{sha256}.png",
  "key": "users/{user_scope}/images/{sha256}.png",
  "already_uploaded": false,
  "headers": {
    "authorization": "AWS4-HMAC-SHA256 ...",
    "x-amz-date": "20260520T000000Z",
    "x-amz-content-sha256": "UNSIGNED-PAYLOAD",
    "Content-Type": "image/png",
    "Content-Disposition": "inline"
  }
}
```

## GET /file/sign/upload/document

Returns a PUT signature for a document object.

Query parameters:

| Name | Required | Description |
| --- | --- | --- |
| `filename` | yes | File SHA-256 digest as 64 lowercase or uppercase hex chars. A trailing `.sha256` suffix is accepted and removed. |
| `ext` | yes | One of `pdf`, `doc`, `docx`, `xls`, `xlsx`, `txt`, `md`. A leading `.` is accepted and removed. |

The server checks whether the object already exists in S3. If it exists, `already_uploaded` is `true`; the client can skip uploading.

Response shape is the same as image upload.

## PUT /file/sign/upload/avatar

Uploads the current user's avatar through the file service. The client sends
the file bytes as the request body; the service validates the file type and uploads
the object to S3/R2.

Query parameters:

| Name | Required | Description |
| --- | --- | --- |
| `ext` | yes | One of `jpg`, `jpeg`, `png`, `webp`, `gif`. A leading `.` is accepted and removed. |

Request body: raw file bytes.

Response `data`:

```json
{
  "bucket_id": "avatar",
  "key": "avatars/{user_scope}",
  "url": "https://assets.example.com/avatars/{user_scope}",
  "sha256": "{server_calculated_sha256}",
  "size": 12345,
  "already_uploaded": false
}
```

## PUT /file/sign/upload/image

Uploads an image through the file service. The client sends only `ext` and
the raw file bytes; the service calculates SHA-256, validates the file header, and
stores the object as `users/{user_scope}/images/{sha256}.{ext}`.

Query parameters:

| Name | Required | Description |
| --- | --- | --- |
| `ext` | yes | One of `jpg`, `jpeg`, `png`, `webp`, `gif`. A leading `.` is accepted and removed. |

If the same object already exists, `already_uploaded` is `true` and the service
skips the S3/R2 PUT.

Response `data`:

```json
{
  "key": "users/{user_scope}/images/{sha256}.png",
  "url": "http://127.0.0.1:9000/private-bucket/users/{user_scope}/images/{sha256}.png",
  "sha256": "{server_calculated_sha256}",
  "size": 12345,
  "already_uploaded": false
}
```

## PUT /file/sign/upload/document

Uploads a document through the file service. The client sends only `ext`
and the raw file bytes; the service calculates SHA-256, validates the file header
or UTF-8 text payload, and stores the object as
`users/{user_scope}/docs/{sha256}.{ext}`.

Query parameters:

| Name | Required | Description |
| --- | --- | --- |
| `ext` | yes | One of `pdf`, `doc`, `docx`, `xls`, `xlsx`, `txt`, `md`. A leading `.` is accepted and removed. |

Response shape is the same as server-side image upload.

## GET /file/sign/upload/media

Returns a direct S3 PUT signature for a private video. `filename` is the file
SHA-256 and `ext` is one of `mp4`, `mov`, or `m4v`. Objects are stored as
`users/{user_scope}/media/{sha256}.{ext}` in the configured `media` category.

## PUT /file/sign/upload/media

Audio extension: GET/PUT also accept `wav` (`audio/wav`) and `mp3`
(`audio/mpeg`) in the same private media category. PUT checks RIFF/WAVE or
ID3/MPEG Layer III headers; consumers must still decode and validate duration.
The existing 50 MiB upload cap applies; the transcription plugin imposes a
stricter 10 MiB / 60 second limit.

Uploads raw private video bytes through file-service. `ext` is one of `mp4`,
`mov`, or `m4v`; the matching content type is `video/mp4` or
`video/quicktime`. The service verifies an ISO Base Media `ftyp` signature,
calculates SHA-256, and deduplicates by content. Request bodies are limited to
50 MiB. Larger media requires a separately designed multipart upload flow.

## GET /file/sign/access

Returns a direct URL for a `public` category or a presigned GET URL for a
`private` category owned by the current user.

Query parameters:

| Name | Required | Description |
| --- | --- | --- |
| `bucket_id` | no | Logical storage category, such as `image`, `document`, or `media`; never a real bucket name. Omit it only for recognized legacy key formats. |
| `key` | yes | Object key or full object URL. Only current-user private avatar/image/document/media keys are allowed. |

Allowed key prefixes:

```text
users/{user_scope}/images/
users/{user_scope}/docs/
users/{user_scope}/media/
avatars/{user_scope}
```

Response `data`:

```json
{
  "bucket_id": "image",
  "method": "GET",
  "download_url": "http://127.0.0.1:9000/private-bucket/users/{user_scope}/images/{sha256}.png?...",
  "key": "users/{user_scope}/images/{sha256}.png"
}
```

## GET /file/sign/delete

Returns a DELETE signature for an object owned by the current user.

Query parameters:

| Name | Required | Description |
| --- | --- | --- |
| `bucket_id` | no | Logical storage category, such as `avatar`, `image`, or `document`. Omit it only for legacy avatar/image/document key formats. |
| `key` | yes | Object key or full object URL. Current-user avatar, private image, document, and media keys are allowed. |

Allowed keys:

```text
avatars/{user_scope}
users/{user_scope}/images/*
users/{user_scope}/docs/*
users/{user_scope}/media/*
```

Response `data`:

```json
{
  "bucket_id": "document",
  "method": "DELETE",
  "delete_url": "http://127.0.0.1:9000/private-bucket/users/{user_scope}/docs/{sha256}.pdf",
  "key": "users/{user_scope}/docs/{sha256}.pdf",
  "headers": {
    "authorization": "AWS4-HMAC-SHA256 ...",
    "x-amz-date": "20260520T000000Z",
    "x-amz-content-sha256": "UNSIGNED-PAYLOAD",
    "Content-Type": null,
    "Content-Disposition": null
  }
}
```
